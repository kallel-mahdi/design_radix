# Session 10.5 Plan: PDF Metadata Extraction & Auto-Reference Creation

**Session**: 10.5
**Goal**: Enable Zotero-style PDF upload workflow (drag-drop PDF → auto-extract metadata → create reference)
**Priority**: Critical UX gap identified during Session 10 user testing
**Estimated Time**: 1-2 days (16-20 hours)
**Status**: PLANNED
**Date Created**: 2025-11-24

## Executive Summary

### Problem Statement

**Current Workflow (Post-Session 10)**:
1. User clicks "New Reference" button
2. User manually enters title, authors, year, venue, DOI, etc.
3. User saves reference
4. User uploads PDF to existing reference
5. **Result**: 3-5 minutes of manual data entry per paper, high error rate (typos)

**Expected Workflow (Zotero-equivalent)**:
1. User drag-drops PDF onto library view
2. Backend extracts metadata from PDF (DOI, title, authors)
3. Frontend shows preview: "Found 'Smith et al. 2023'. Confirm?"
4. User confirms → reference created with PDF attached
5. **Result**: <30 seconds per paper, zero typos, ~70% success rate (papers with DOI)

### Impact

- **User Experience**: Reduces friction from 3-5 minutes to <30 seconds per import
- **Data Quality**: Eliminates manual transcription errors
- **Zotero Parity**: Matches expected behavior from reference managers
- **Adoption**: Critical feature for power users managing 100+ papers

### Solution Overview

**Phase 1 (This Session)**:
- Use `pdf-parse` npm package for text extraction
- Parse extracted text for DOI using regex
- If DOI found → enrich via existing Crossref API (Session 6)
- If no DOI → create reference from filename (fallback)
- Frontend: drag-drop zone with metadata preview modal

**Deferred to Phase 2**:
- GROBID integration (ML-powered extraction for scanned PDFs)
- ISBN/arXiv ID parsing and enrichment
- OCR support for scanned documents

**Rationale**: Phase 1 handles ~70% of academic papers (those with DOI) with minimal complexity. GROBID adds significant infrastructure overhead (Java service, Docker) for marginal gain (~20-30% more papers).

## Research Findings

### How Zotero Handles PDF Uploads

**Source**: Explore agent investigation of `zotero/` codebase (2025-11-24, corrected 2025-01-24)

**Zotero Drag-Drop PDF Import** (`itemTree.jsx:2242-2675`):
- ✅ Zotero DOES support drag-drop PDF import from file manager onto item list
- Triggers `autoRecognizeItems()` for automatic metadata extraction
- This is core functionality, NOT just for collection management

**Zotero's 3-Stage Pipeline**:

1. **PDF Text Extraction** (`pdfWorker/manager.js`):
   - Extracts text from first 5 pages using pdf.js in a Web Worker
   - Parses PDF structure for embedded metadata (title, authors, DOI, ISBN, arXiv ID)
   - Returns structured JSON with recognized identifiers

2. **Server-Side Recognition** (`recognizeDocument.js:411-430`):
   - Sends extracted JSON to remote recognition server
   - Server uses ML/heuristics to identify DOI/arXiv/ISBN with high confidence
   - Returns matched identifiers only (no false positives)

3. **Metadata Enrichment** (`recognizeDocument.js:432-530`):
   - Fetches full metadata from external APIs based on identifiers
   - Priority: arXiv (if arXiv ID) → Crossref (if DOI) → ISBN (if ISBN) → Title fallback
   - Creates reference with enriched data + attaches PDF

**Key Takeaway**: Zotero uses a sophisticated multi-stage approach with a proprietary recognition server. We simplify by using regex DOI extraction + Crossref API (which we already have).

### Production-Ready Solutions

**Option 1: pdf-parse (Recommended for Phase 1)**
- **Type**: npm package, pure Node.js
- **Capabilities**: Extract text from PDF (all pages or first N pages)
- **Performance**: Fast (~100ms for 10-page PDF)
- **Complexity**: Low (10 lines of code)
- **Limitations**: No identifier recognition (requires regex parsing), no OCR

**Option 2: GROBID (Recommended for Phase 2)**
- **Type**: Java-based REST service
- **Capabilities**: ML-powered metadata extraction (title, authors, affiliations, references, 68 granular labels)
- **Performance**: 8.4 PDF/s (header extraction), 87% F1-score on PubMed Central
- **Complexity**: High (requires Docker service, Java runtime, external HTTP calls)
- **Production Use**: ResearchGate, Semantic Scholar, Internet Archive Scholar
- **Limitations**: Adds infrastructure dependency

**Decision**: Use pdf-parse for Phase 1 (MVP), GROBID for Phase 2 (production polish).

## Architecture Decision

### Approach: pdf-parse + Crossref API

**Flow**:
```
1. User drops PDF onto library view
   ↓
2. Frontend: Send PDF to POST /references/from-pdf (multipart upload)
   ↓
3. Backend: Save PDF to temporary storage
   ↓
4. Backend: Extract text from first 5 pages using pdf-parse
   ↓
5. Backend: Parse text for DOI using regex: /10\.\d{4,}\/[^\s]+/i
   ↓
6. If DOI found:
   → Call CrossrefService.fetchMetadata(doi)
   → Map to ReferenceInput
   → Create reference with hasPdf=true + PDF metadata
   → Return { reference, extractedMetadata: { doi, source: 'crossref' } }
   ↓
7. If NO DOI found:
   → Extract title from filename (remove .pdf, replace hyphens with spaces)
   → Create reference with title, type='article', empty authors
   → Return { reference, extractedMetadata: { source: 'filename-fallback' } }
   ↓
8. Frontend: Show success toast notification
   → "Added: {title} (from Crossref)" or "Added: {title} (from filename)"
   → Auto-select newly created reference in table
   → No modal, no preview - create automatically (Zotero-style)
   ↓
9. User can edit reference afterward if needed (via ReferenceModal)
```

**Error Handling**:
- Corrupt PDF → Catch pdf-parse error → Return 400 with "Invalid PDF file"
- Crossref API failure → Fall back to filename extraction (graceful degradation)
- Duplicate DOI → Check if reference with DOI exists → Return 409 Conflict

**Performance**:
- pdf-parse: ~100ms for 10-page PDF (only reading first 5 pages)
- Crossref API: ~500ms (Session 6 has retry logic)
- Total: ~600ms end-to-end

**Why 5 pages?**: Zotero only uses first 5 pages for performance. DOI typically appears on page 1 (title page) or page 2 (abstract).

### Technology Stack

**Backend**:
- `pdf-parse` (npm package, ~500KB, MIT license)
- `@types/pdf-parse` (TypeScript definitions)
- Existing: `CrossrefService` (Session 6)
- Existing: `ReferenceService` (Session 1)
- Existing: `uploadPdf` Multer middleware (Session 10)

**Frontend**:
- New: "Import from PDF..." menu item (in Import dropdown)
- New: Drag-drop handlers on Library/ReferenceTable component
- New: `useCreateReferenceFromPdfMutation` hook
- Existing: `apiClient.post()` (Session 1)
- Existing: Toast notifications (Session 1)

**No New Components**: Uses existing UI elements (dropdown menu, toast system). No dedicated upload zone.

**No New Infrastructure**: All dependencies are npm packages or existing services.

## Deviations from Original Spec

### 1. Feature Prioritization Change

**Original Plan** (`future-phases.md` lines 305-320):
- PDF metadata extraction listed in Phase 2 (2-3 weeks after MVP)
- Rationale: "Advanced feature, MVP can launch without it"

**Deviation**:
- Moved to MVP as Session 10.5 (immediately after Session 10)
- Rationale: User testing revealed critical UX gap. Manual entry for every PDF is too slow for research workflows. Zotero users expect this feature.

**Impact**: +1-2 days to MVP timeline, but significantly improves user experience and adoption.

### 2. Implementation Approach Simplification

**Original Plan** (implied from Zotero research):
- Full Zotero-equivalent 3-stage pipeline: Text extraction → Server recognition → Metadata enrichment
- Requires external recognition server (similar to Zotero's)

**Deviation**:
- Simplified to 2-stage pipeline: Text extraction (pdf-parse) → Regex DOI parsing → Crossref enrichment
- No external recognition server needed

**Rationale**:
- Zotero's recognition server is proprietary and requires ML infrastructure
- Regex DOI parsing handles ~70% of papers (sufficient for MVP)
- Crossref API already integrated (Session 6)
- GROBID (ML-powered) deferred to Phase 2 for remaining ~30%

**Trade-off**: Lower recognition rate (70% vs 90%) but much simpler implementation.

### 3. Metadata Preview Step Added

**Original Plan**: Not specified in Zotero research

**Deviation**:
- Added metadata preview modal before creating reference
- User can edit extracted data before confirming

**Rationale**:
- Allows user to verify extracted data (especially for filename-fallback cases)
- Prevents creating incorrect references
- Matches expected UX pattern (preview before commit)

**Trade-off**: Adds one extra click, but improves data quality.

### ⚠️ Justified Deviations (Web vs. Desktop UX)

- **Zotero**: `<panel type="arrow">` - persistent popup, stays open after import, supports sequential imports

- **Zotero**: Manual "Retrieve Metadata for PDF" action (right-click menu)

- **Rationale**: Faster web UX, fewer clicks

**3. Single PDF per Reference**:
- **Zotero**: Multiple attachments per item
- **Ours**: One PDF per reference (MVP constraint)
- **Rationale**: Simplifies data model, covers 90% use case

## Appendix: Code Snippets

### Backend: PdfMetadataService Skeleton

```typescript
// src/services/PdfMetadataService.ts
import * as pdfParse from 'pdf-parse';
import { promises as fs } from 'fs';
import { injectable, inject } from 'inversify';
import { TYPES } from '../config/types';
import { CrossrefService } from './CrossrefService';
import { ReferenceService } from './ReferenceService';
import { CreateReferenceInput, Reference } from '@bibliography/shared';
import logger from '../utils/logger';

@injectable()
export class PdfMetadataService {
  constructor(
    @inject(TYPES.ICrossrefService) private crossrefService: CrossrefService,
    @inject(TYPES.IReferenceService) private referenceService: ReferenceService
  ) {}

  async extractTextFromPdf(filePath: string): Promise<string> {
    const dataBuffer = await fs.readFile(filePath);
    const data = await pdfParse(dataBuffer, { max: 5 }); // First 5 pages
    return data.text;
  }

  extractDoi(text: string): string | null {
    const doiRegex = /10\.\d{4,}\/[^\s]+/i;
    const match = text.match(doiRegex);
    return match ? match[0] : null;
  }

  extractTitleFromFilename(filename: string): string {
    return filename
      .replace(/\.pdf$/i, '')
      .replace(/[-_]/g, ' ')
      .trim();
  }

  async createReferenceFromPdf(
    userId: string,
    filePath: string,
    originalName: string
  ): Promise<{ reference: Reference; metadata: any }> {
    try {
      // Extract text
      const text = await this.extractTextFromPdf(filePath);

      // Try DOI first
      const doi = this.extractDoi(text);
      if (doi) {
        logger.info('DOI found in PDF', { doi, filename: originalName });
        const crossrefData = await this.crossrefService.fetchMetadata(doi);
        const input = this.crossrefService.mapToReferenceInput(crossrefData);

        const stat = await fs.stat(filePath);
        const reference = await this.referenceService.create(userId, {
          ...input,
          hasPdf: true,
          pdf: {
            storedPath: filePath,
            originalName,
            size: stat.size,
            mimeType: 'application/pdf',
            uploadedAt: new Date()
          }
        });

        return { reference, metadata: { doi, source: 'crossref' } };
      }

      // Fallback: Create from filename
      logger.info('No DOI found, using filename', { filename: originalName });
      const title = this.extractTitleFromFilename(originalName);
      const stat = await fs.stat(filePath);

      const referenceInput: CreateReferenceInput = {
        type: 'article',
        title,
        hasPdf: true,
        pdf: {
          storedPath: filePath,
          originalName,
          size: stat.size,
          mimeType: 'application/pdf',
          uploadedAt: new Date()
        }
      };

      const reference = await this.referenceService.create(userId, referenceInput);
      return { reference, metadata: { source: 'filename-fallback' } };

    } catch (error) {
      logger.error('PDF metadata extraction failed', {
        error: error instanceof Error ? error.message : String(error),
        filename: originalName
      });
      throw error;
    }
  }
}
```

```typescript
// src/controllers/ReferenceController.ts
async createFromPdf(req: Request, res: Response, next: NextFunction): Promise<void> {
  try {
    const userId = req.headers['x-user-id'] as string;
    if (!req.file) {
      res.status(400).json({
        success: false,
        error: 'NO_FILE',
        message: 'No PDF provided'
      });
      return;
    }

    const { reference, metadata } = await this.pdfMetadataService.createReferenceFromPdf(
      userId,
      req.file.path,
      req.file.originalname
    );

    res.status(201).json({
      success: true,
      message: 'Reference created from PDF',
      data: reference,
      extractedMetadata: metadata
    });
  } catch (error) {
    next(error);
  }
}
```

```typescript
// src/features/library/api/pdf.mutations.ts
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { apiClient } from '../../../common/api/client';
import { useToast } from '../../../common/hooks/useToast';
import { useLibraryStore } from '../store/library.store';

export function useCreateReferenceFromPdfMutation() {
  const queryClient = useQueryClient();
  const { showToast } = useToast();
  const { setActiveReferenceId } = useLibraryStore();

  return useMutation({
    mutationFn: async (formData: FormData) => {
      // Show processing toast
      showToast({
        type: 'info',
        message: 'Processing PDF...',
        duration: 0 // Indefinite until success/error
      });

      return apiClient.post<{ reference: Reference; extractedMetadata: any }>(
        '/references/from-pdf',
        formData,
        { headers: { 'Content-Type': 'multipart/form-data' } }
      );
    },
    onSuccess: ({ reference, extractedMetadata }) => {
      queryClient.invalidateQueries({ queryKey: ['references'] });

      // Auto-select newly created reference
      setActiveReferenceId(reference.id);

      // Show success toast with source indicator
      const source = extractedMetadata.source === 'crossref' ? 'from Crossref' : 'from filename';
      showToast({
        type: 'success',
        message: `Added: ${reference.title} (${source})`,
        duration: 5000,
        action: { label: 'View', onClick: () => setActiveReferenceId(reference.id) }
      });
    },
    onError: (error: any) => {
      if (error.message.includes('Invalid PDF')) {
        showToast({ type: 'error', message: 'Invalid PDF file', duration: 5000 });
      } else if (error.message.includes('already exists')) {
        showToast({ type: 'error', message: 'Reference already exists', duration: 5000 });
      } else {
        showToast({ type: 'warning', message: 'Reference created from filename. Edit to add details.', duration: 7000 });
      }
    }
  });
}
```

```typescript
// src/features/library/components/Library.tsx (or ReferenceTable.tsx)
import { useState } from 'react';
import { useCreateReferenceFromPdfMutation } from '../api/pdf.mutations';

export function Library() {
  const [isDragging, setIsDragging] = useState(false);
  const mutation = useCreateReferenceFromPdfMutation();

  const handleDragOver = (e: React.DragEvent) => {
    e.preventDefault();
    setIsDragging(true);
  };

  const handleDragLeave = () => {
    setIsDragging(false);
  };

  const handleDrop = (e: React.DragEvent) => {
    e.preventDefault();
    setIsDragging(false);

    const file = e.dataTransfer.files[0];
    if (file?.type === 'application/pdf') {
      const formData = new FormData();
      formData.append('file', file);
      mutation.mutate(formData);
    } else {
      // Show error toast for non-PDF files
      showToast({ type: 'error', message: 'Only PDF files are supported', duration: 5000 });
    }
  };

  return (
    <div
      onDragOver={handleDragOver}
      onDragLeave={handleDragLeave}
      onDrop={handleDrop}
      className={isDragging ? 'ring-2 ring-green-500' : ''}
    >
      {/* Rest of library content (toolbar, table, etc.) */}
    </div>
  );
}
```
